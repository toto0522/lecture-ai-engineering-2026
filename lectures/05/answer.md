- 検索だけを実行して見つかったページと、その本文で確認できたこと：
  - `uv run python -m app.retrieval "LoRA QLoRA 違い"` を実行し、上位5件の中に **第2回・PDF p.52** が含まれること、および本文に「元の重みを固定して差分を学習するLoRA」「元の重みを4bitに圧縮するQLoRA」の説明が記載されていることを確認した。
- `--trace` で見えたツール呼び出し（ツール名・引数・回数、Treeでたどった目次など）：
  - ベクトル検索：`search_materials(query='LoRA QLoRA 固定 学習')` を1回呼び出し、上位ページを取得して回答。
  - Tree：`browse_tree` を計4回呼び出し、「講義一覧 → 第2回 → 該当章 → p.52」の順に階層をたどってページ全文を取得した（モデル応答は計5回）。
  - Graph：`search_graph` を1回呼び出し、検索上位の入口（seeds）から前後ページ・共通用語をたどった拡張候補（expanded）を含めて取得した。
- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：
  - 今回の質問は第2回 p.52 の1ページのみで答えが完結する単一ページ型の質問だったため、基本のベクトル検索で十分な根拠を取得できた。Graphでは周辺ページも追加取得したが、回答の正確性自体は変わらず、入力トークン数とコストがわずかに増加する結果となった。
- 今回の用途に採用したい方式と、その理由・比較条件の限界：
  - 単一ページで完結する質問が多い場合は、応答速度・トークン数・コストのバランスが最も良い **ベクトル検索（基本RAG）** を採用したい。一方で、章やページをまたぐ複雑な質問では、関係ページをたどれる **Graph** や構造をたどる **Tree** が有効になるため、質問の性質に応じた使い分けが必要。
  - 比較条件の限界として、全文投入のみ対象範囲が全9資料（438ページ）と広く、他の3方式（214ページ）と条件が完全には揃っていない点がある。
- 気づき・疑問：
  - 全文投入でも正答はできるが、入力トークン数が約11.7万トークンと非常に大きく、1回あたりのコストがベクトル検索の約25倍になることを実測で確認できた。
  - Treeは人間が目次をめくるのと近い自然な探索を行うが、階層を1段ずつ降りるたびにLLMとの往復（応答回数）が増えるため、時間とトークン消費が大きくなる。
