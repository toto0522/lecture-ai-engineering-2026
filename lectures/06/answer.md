## 宿題

<!-- 基礎・実装・発展のどれか1つに取り組めば完了です。 -->

- 取り組んだレベル：実装
- やったこと：
  1. `app/tools.py` に、指定した回の講義要点と用語集データから確認クイズ作成用の資料を返す関数 `make_quiz(lecture: int)` を実装した。存在しない回番号が渡された場合は、単なるエラーではなく「データが存在しない理由」と「有効な回番号の一覧（01, 02, 03, 04, 06）」を明記したエラーメッセージを返すように設計した。
  2. `app/mcp_server.py` に `server.tool()(tools.make_quiz)` を1行追加し、MCP サーバーのツール（`glossary_make_quiz`）として公開した。
  3. `uv run python -m app.mcp_agent --trace` を使い、範囲外の質問（「第99回のクイズを作って」）と正常な質問（「第3回のクイズを作って」）を実行してモデルの挙動を確認した。
- 結果：
  - 範囲外の質問（`第99回のクイズを作って`）に対して、`[tool call] glossary_make_quiz({'lecture': 99})` が実行され、ツールからのエラーメッセージを受け取ったモデルが「第99回の講義データは存在しないこと」「指定できる有効な回は第1回〜第4回・第6回であること」を整理してユーザーに再入力を促す回答を生成した（モデル応答 2回）。
  - 正常な質問（`第3回のクイズを作って`）では、第3回の講義要点と用語データをもとに4択の確認クイズが正しく作成された。
- 気づき・疑問：
  - エージェント本体（`app/mcp_agent.py`）や設定ファイル（`app/mcp_servers.json`）を一切変更しなくても、サーバー側にツールを追加するだけでエージェント起動時に動的に認識される MCP の疎結合な仕組みを実感できた。
  - エラー時に「何がダメで、代わりに何を指定すればよいか」を具体的なテキストで返すことで、ツール側で複雑な例外処理を実装しなくても LLM 自身が状況を理解して適切な案内（リカバリー）を行えることが確認できた。
